fix: 复合命令拒绝记录归属到真正违规的段（不再误记 cd）

现象：审计里出现一堆「cd 被拒绝」的记录，看日志的人会以为 cd 被禁了。
实际是 `cd /tmp && <递归删除> x` 这类复合命令 —— 整条被策略拒绝
（行为正确），但 recordIntent 取的是命令首段，于是工具名记成了 cd。

这不是显示问题，是记录失真的问题：
- 按工具名统计时，危险操作全被算到无害的 cd/echo 头上
- 安全复盘时看不到真正的违规主体

修法：用引擎已返回的 verdict.match（正则命中片段）在命令里定位，
再按 && / || / ; / | / 换行 切段，取命中片段所在的那一段作为归属。

now:
  cd /tmp && <删除> rtk-dev   →  tool=rm  target=rtk-dev
  echo start; <删除> logs     →  tool=rm  target=logs

附带：
- 记录里写入 target（动作后的首个非选项参数），一眼看出操作对象
- meta 保留 full_command（整条命令）+ attributed_to（归属），
  Web 控制台详情弹窗可见，既知道归谁也能看到原始上下文

实测四条复合命令归属全部正确。测试 58→60。
