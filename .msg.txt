fix: 复合命令整类漏审计（带管道的内部调用完全无痕）

真实事故：用户执行
  shandian lane service-detail --env-id 40 --group ecrobot --name voc-admin 2>&1 | tr -d '\r'
执行成功，但审计库里一条记录都没有。

根因是把"不能改写"和"不用记录"错绑在同一个条件上：
  const COMPLEX = /[|;&><`]|\$\(|\|\||&&/;
  if (isComplex) return process.exit(0);

不改写是对的（`vig shandian ... | tr` 会让管道作用于 vigile 而非原命令，
破坏语义），但直接 return 导致所有含管道/重定向/&&/; 的命令整类成为
审计盲区 —— 这覆盖了排查场景里极常见的一类调用。

修法：拆开两个概念。复合命令不改写，但按 shell 分隔符切开逐段记录：
- shandian lane service-detail ...  → 记 tool=shandian target=service-detail
- | tr -d '\r'                       → 噪声名单，跳过
- meta 保留整条命令原文 + 该段原文

配套改动：
- 新增 vigile call-batch：一次进程写入 N 条。逐条 spawn 在长管道上会
  撞 hook 的 4s 守护超时，批量后稳定在 ~150ms
- call-batch 加入 RESERVED 子命令列表（否则被代理形态当成外部命令，
  exit 127 —— 开发过程中真实踩到）
- 噪声名单补 tr/sed/awk/cut/sort/uniq/xargs/tee/jq/column/iconv：
  管道里的格式化段不是"调用"，不该占审计条目

实测四种复合形态：
  cd /tmp && kubectl get pods      → 记 2 条
  kubectl get pods 2>&1 | head -20 → 记 1 条（head 噪声）
  shandian status; jira get BUG-1  → 记 2 条
  cat x.log | grep ERROR           → 0 条（全噪声）

测试 60→62。
